# Sweet Q&A 索引重建完成报告

## 问题总结

### 原始问题
Sweet Q&A的references检索数量有问题，实际有83个PDF文献，但检索结果受限。

### 根本原因
1. **RecursionError问题**：llama-index默认使用`SentenceSplitter`，在处理超长文本时会导致递归深度超限
2. **嵌入维度不匹配**：旧索引使用768维零向量构建，但查询时使用512维真实嵌入模型，导致维度不匹配
3. **Score为NaN问题**：零向量导致相似度计算时分母为0，所有score都是NaN

## 解决方案

### 1. 修改文本分割策略
**文件**: `persistent_storage.py`

修改了`_build_new_index`方法，配置了更安全的文本分割器：
```python
text_splitter = SentenceSplitter(
    chunk_size=512,  # 减小chunk大小（原1024）
    chunk_overlap=50,  # 减小重叠（原200）
    paragraph_separator="\n\n",
    secondary_chunking_regex="[^,.;。？！]+[,.;。？！]?",  # 简单的句子分割
)
```

### 2. 统一嵌入模型配置
**文件**: `persistent_storage.py`

- 修改了`_configure_models`方法，优先使用真实的bge-small-zh-v1.5嵌入模型（512维）
- 使用正确的模型路径：`models/models--BAAI--bge-small-zh-v1.5/snapshots/7999e1d3359715c523056ef9478215996d62a620`
- 简化了`_build_new_index`方法，移除重复的嵌入模型创建逻辑，统一使用`Settings.embed_model`

### 3. 增加递归深度限制
在索引重建脚本中设置：
```python
sys.setrecursionlimit(3000)
```

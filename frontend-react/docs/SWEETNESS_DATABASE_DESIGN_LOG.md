## 2026-08-03 第 1 轮

### D-001 分子详情页增加“提及到的论文”

**状态：建议纳入**

**用户偏好**

- 在 Sweetness Database 的单个分子详情页展示相关论文。
- 论文条目可以点击，作用类似优秀数据库中的书目列表。

**现有基础**

- 当前 RAG 已能按论文聚合检索结果，并向前端返回 `title`、`authors`、`journal`、`year`、`doi`、`score`。
- QA 页面已经有 ReferenceCard 和 DOI 外链，可复用数据契约与部分交互。
- 化合物 API 当前尚未返回文献关联，需要新增独立的 literature 查询能力。

**关键产品判断**

- 该功能价值高：它能把“分子数据”与“证据来源”连接起来，是正式科研数据库建立可信度的重要部分。
- 不应把所有向量检索结果都标为“提及该分子”。必须区分：
  - `Direct mentions`：正文中明确出现分子名称、同义词、CAS、CID 或其他稳定标识。
  - `Related evidence`：RAG 语义检索认为相关，但可能没有直接点名该分子。
- 推荐区块名称暂定为 `Literature & Evidence`，内部再分“直接提及”和“相关证据”。

**推荐条目字段**

- 论文标题、作者、期刊、年份、DOI/PMID。
- 关系标签：直接提及 / 甜度测定 / 感官研究 / 食品应用 / 安全性 / 机制 / 预测。
- 命中证据片段，后续条件允许时增加页码或章节位置。
- 数据来源与相关性说明；不直接向前端暴露服务器文件路径。

**推荐实现原则**

- 页面首次打开优先读取预计算或缓存的“分子-论文关联”，避免每次触发完整 RAG 导致慢和结果漂移。
- 精确提及由名称、同义词和标识符匹配建立；语义 RAG 作为补充召回。
- 点击优先打开 DOI/PMID；本地全文需通过受控的 paper ID/查看接口，不使用原始 `file_path`。
- 可在后续版本增加 `Ask these papers`，把所选分子的证据集合带入 Sweetness Q&A。

**待确认**

- 首版是否同时展示“直接提及”和“相关证据”，还是只展示更稳妥的直接提及。
- 是否需要站内 PDF 阅读器及命中段落定位。

### D-002 分子详情页采用完整但领域化的锚点导航

**状态：建议纳入**

**用户偏好**

- 借鉴 ChEMBL 和 PubChem 的侧边目录，让长详情页的信息完整且可快速跳转。
- PubChem 的食品添加剂与配料内容和 SweetSeek 很契合。
- 不照搬 PubChem 的 20 多个大类，避免内容过多。

**推荐首版信息架构（8 个一级区块）**

1. `Overview`：名称、分类、关键标识、二维结构、核心甜度结论。
2. `Sweetness & Sensory`：相对甜度及范围、参照物、测定条件、时间曲线、余味和其他感官描述。
3. `Structure & Identifiers`：分子式、分子量、SMILES、InChI/InChIKey、CAS、PubChem CID、同义词与异构体。
4. `Physicochemical Properties`：LogP、TPSA、氢键、溶解性、pKa、稳定性等；缺失字段不展示空卡片。
5. `Food Sources & Applications`：天然来源、食品类别、添加剂/配料角色、典型用量、加工和储存稳定性、复配信息。
6. `Literature & Evidence`：直接提及论文、相关证据、证据片段和来源。
7. `Safety & Regulation`：ADI、安全评估、毒理摘要、FDA/EFSA/JECFA 及不同地区准入状态；所有结论必须有来源和日期。
8. `Related Compounds & Data Provenance`：结构/感官相似分子、可替代物、外部数据库链接、字段级来源、置信度和更新时间。

**按数据存在才显示的可选区块**

- `Receptor & Mechanism`：TAS1R2/TAS1R3、结合位点、实验或预测结果。
- `Spectra`、`Patents`、`Manufacturing`：首版不作为固定导航，仅在数据覆盖足够时加入。

**导航交互原则**

- 桌面端使用粘性侧栏，并高亮当前滚动区块；移动端改为可折叠目录或顶部 section selector。
- 一级导航控制在 7-9 项；二级内容在正文内部折叠。
- 无数据的区块不占据一级导航，避免出现大量 `N/A`。
- 每个关键数值同时显示来源、实验条件或 `Predicted` 标签，避免把不同口径的甜度值混成一个确定数字。

## 累计方向

- 正式版基调：数据详情与证据保持克制、可信；探索和比较功能可以更具视觉冲击力。
- 当前不进入实施阶段；待多轮功能讨论结束后统一排序、拆分版本和形成开发 plan。

## 2026-08-03 第 2 轮

### D-003 Database 入口改为可交互的 Sweetness Atlas

**状态：建议纳入（用户认可方向）**

**用户偏好**

- 进入 Database 后，第一眼不再是朴素列表，而是类似“分子云”的总体视觉。
- 分子可以点击并进入详情，同时提供总览和搜索入口。

**产品定义**

- 正式名称暂定为 `Sweetness Atlas`，它是实际的数据探索器，不是宣传 Hero 或随机漂浮装饰。
- 默认使用有科学依据的二维分子地图：点之间越接近，表示结构或所选属性越相似。
- 每个点对应一个可进入详情页的数据库记录；悬停显示二维结构、名称、相对甜度、分类和证据状态。
- 点击进入详情页；返回时必须恢复 Atlas 的缩放、筛选、搜索和选中状态。

**推荐首屏结构**

1. 顶部工具栏：全局分子搜索、结构/属性筛选、视图切换。
2. 紧凑总览：收录分子数、具有甜度数据的数量、主要类别、文献覆盖率和最近更新时间。
3. 主画布：占据首屏主体的 Sweetness Atlas，可缩放、平移、框选和重置。
4. 图例与筛选：天然/合成等分类、甜度范围、证据状态；筛选后地图与结果数同步更新。
5. 列表入口：提供 `Atlas / Property Plot / List` 分段切换，不能强迫所有用户通过图形查找。

**建议的两种科学视图**

- `Similarity Map`：基于 ECFP4/MACCS 等结构特征降维，适合发现化学结构簇。UMAP 两个轴本身没有直接物理含义，界面必须明确说明“距离代表局部结构相似性”。
- `Property Plot`：用户选择明确坐标，例如分子量、LogP、TPSA、相对甜度；更适合解释和比较。

**数据边界**

- 当前 `data/compounds_sweet.xlsx` 只有 56 条正式分子记录。
- 当前特征矩阵有 3,846 个样本、1,407 个特征，其中含 881 个 sweet 和 2,965 个 non-sweet 机器学习样本。
- 首屏 Atlas 默认只能把正式数据库记录作为可点击实体。训练集化学空间如需展示，必须另设模式并明确标记，不能把训练样本冒充成正式收录分子。
- `data/processed/master.parquet` 当前读取失败，实施前需要修复或重新生成，并验证特征行与稳定 compound ID 的一一映射。
- 天然/合成、糖类/糖醇/糖苷/蛋白等颜色分类目前不在 56 条基础表字段中，需要先建立受控分类字段。

**视觉与交互原则**

- 白色或浅灰工作台为主，Atlas 可使用较深的局部画布模式，但不做全站赛博大屏。
- 高密度状态使用点；仅在悬停、选中或放大后显示分子缩略图，避免 2D 结构互相遮挡。
- 搜索命中后自动定位并高亮目标，同时保留直接进入详情的操作。
- 移动端不照搬桌面大画布：使用简化地图、底部筛选抽屉和列表回退。

### D-004 分子详情页增加局部相似性网络

**状态：建议纳入（用户认可方向）**

**用户偏好**

- 在详情页展示当前分子与相似分子的关系网络。

**与 Sweetness Atlas 的分工**

- Atlas 是全局地图，回答“整个数据库有哪些簇，我可以去哪里探索”。
- Similarity Network 是当前分子的局部邻域，回答“它与哪些分子相似，以及相似的依据是什么”。

**推荐首版范围**

- 中心节点为当前分子，只展示最相关的 8-15 个邻居，避免网络变成不可读的毛线团。
- 首版优先提供可重复验证的 `Structural similarity`：使用相同指纹和 Tanimoto 分数，边上显示具体相似度。
- 同时可提供 `Sweetness proximity`：按对数甜度距离寻找相近分子，并明确它不是结构相似。
- 点击邻居可查看简要预览；提供 `Open details` 和 `Compare`，比较模式建议最多 3 个分子。
- 提供相似度阈值、关系类型切换、图例和重置，不默认同时显示所有关系。

**后续关系类型（需要新增数据后再启用）**

- 感官轮廓相似、共同余味、共同食品来源、共同受体/结合位点。
- 每种边必须有独立图例和来源；预测关系显著标记 `Predicted` 与置信度。

## 累计方向（第 2 轮更新）

- Database 默认入口由列表升级为 `Sweetness Atlas`，但列表仍是一等视图。
- 全局 Atlas 与局部 Similarity Network 分开设计，共用稳定 compound ID、结构指纹和分类数据。
- 正式版数据对象与机器学习训练样本必须在产品和接口层明确分离。

### D-005 当前阶段以前端正式原型为主，56 个分子仅作测试数据

**状态：已确认**

**用户说明**

- 数据库仍在搭建，当前主要目标是完成前端设计。
- 现有五十多个分子可以作为交互和视觉测试数据，不代表正式数据库规模或最终字段覆盖。

**阶段策略**

- 当前先确定信息架构、视觉层级、响应式布局、交互状态和组件边界，不等待数据库完善。
- 56 个分子足以验证 Atlas 的缩放、悬停、搜索定位、筛选、框选、详情跳转和返回状态恢复。
- 相似性网络可用现有结构字段验证节点、连线、阈值、预览和比较流程。
- 前端组件通过稳定的数据契约接收数据；后续扩充数据库时替换 API 数据，不重写页面结构。

**原型数据规则**

- 可以为测试布局补充明确标记的 mock 字段或空状态，但不能把虚构值展示成真实科研结论。
- 界面暂时显示真实的当前记录数，或使用 `Prototype dataset` 标识；不得宣称尚不存在的 `500+ records`。
- 数据缺失时测试 loading、empty、partial、error 和 predicted 状态，避免只设计“所有字段都完整”的理想页面。
- 天然/合成、类别、证据等级等尚未建立的字段，应先定义枚举和展示规则，再由未来数据管线填充。

**对设计决策的影响**

- 前端设计可以保留未来需要的 Literature、Food Applications、Safety、Similarity 等模块，即使当前数据暂不完整。
- 首版原型应优先把 Atlas、搜索、列表、详情页导航和相似性网络的主流程做完整。
- 数据导入、字段清洗、RAG 关联和科学审核在最终实施 plan 中作为独立工作流，不与纯视觉原型混为一项。

## 累计方向（第 3 轮更新）

- 当前交付目标是可扩展、可真实操作的前端正式原型，而不是等待数据库建成后再开始设计。
- 56 个测试分子用于验证体验；所有数量、证据和科学状态必须诚实标识。

## 2026-08-03 第 4 轮

### D-006 正式前端的风险清单与优先级约束

**状态：已记录，待最终 plan 分配解决阶段**

**当前判断**

- 已确定的整体方向合理，不需要推翻：以 Sweetness Atlas 作为探索入口，以搜索、列表和详情页保证实际可用性，以 Literature 与 Similarity Network 建立领域特色。
- 最大风险不是视觉实现，而是科学语义、数据契约和范围控制。

**高风险：开发前必须明确**

1. `Relative Sweetness` 不是无条件的单一常数：可能随浓度、基质、温度、pH、参照物和感官方法改变。详情页应支持数值范围、条件和来源，不能只显示一个醒目的倍数。
2. 结构相似不等于味觉相似：Atlas 与 Similarity Network 必须明确关系类型，不能让用户从距离或连线推断甜度机制。
3. 数据契约尚未稳定：现有 56 条表缺少类别、食品应用、证据等级和监管字段。前端应先定义字段状态和枚举，避免未来数据库扩充时重写页面。
4. “直接提及论文”与“RAG 语义相关论文”必须分开，相关性分数不能冒充引用证据。
5. 当前正式记录与机器学习训练样本数量、身份不同，所有视图和 API 必须使用稳定 compound ID 并显式区分数据层级。

**中风险：通过原型验证**

1. 56 个点的 Atlas 可能显得稀疏；应通过布局、聚类标签、悬停结构和属性视图增强信息量，而不是添加虚假节点。
2. UMAP 结果会随特征选择和参数变化，且坐标无直接物理意义；需要固定版本、保存坐标与算法元数据。
3. 全局 Atlas、局部网络、雷达图、时间曲线和 3D 同时上线会造成视觉竞争；一个页面只保留一个主可视化。
4. 桌面大画布迁移到移动端可能不可用，需要列表和简化交互作为一等回退，而不是缩小桌面界面。
5. 当前 SweetSeek 的蓝色、渐变、圆角卡片风格与正式数据工作台的克制风格存在差异，需要先确定 Database 是延续全站风格还是建立受控的子系统主题。

**暂不确定的产品问题**

- 第一目标用户是食品科研人员、配方工程师、学生，还是公众；这会影响术语、默认信息密度和安全内容表达。
- Atlas 默认展示结构相似空间还是可解释的属性坐标。
- 天然/合成、糖/糖醇/糖苷/蛋白等分类体系由什么标准维护。
- 感官时间曲线、食品应用和监管数据最终能否达到足够覆盖率。
- 本地论文是否允许站内阅读，以及索引能否稳定提供页码和证据片段定位。

**建议的前端验证顺序**

1. 先完成可用骨架：搜索、列表、详情页、返回状态和响应式导航。
2. 再完成一个主视觉：Sweetness Atlas，同时保留 Property Plot 与 List。
3. 然后增加局部 Similarity Network 和最多三项比较。
4. 文献、食品、安全等数据区块先完成组件与空状态，再接真实数据。
5. 感官时间曲线与 3D 结构作为数据充分后的增强，不与首轮主流程抢优先级。

## 累计方向（第 4 轮更新）

- 保留现有总体方案，但开发时必须采用逐层验证，避免一次实现全部可视化。
- 科学条件、证据来源和数据状态属于界面核心内容，不是上线前再补的注释。

## 2026-08-03 第 5 轮

### D-007 推荐的第一版前端范围（V1）

**状态：建议方案，等待用户最终确认**

**版本定位**

- V1 是使用 56 个测试分子的完整、可操作前端原型，不是最终数据库，也不是只有静态效果的概念 Demo。
- 默认目标用户暂定为食品科学研究人员、研究生和配方研发人员；信息表达专业，但不过度堆叠术语。
- 核心用户旅程：发现分子 -> 搜索/筛选 -> 查看详情 -> 探索相似分子 -> 加入比较。

**V1 必须完成：Database 入口**

1. 紧凑页面头部：`Sweetness Atlas`、`Prototype dataset` 状态、真实记录数和更新时间。
2. 全局搜索：支持名称、CID、分子式；搜索结果可以直接定位 Atlas 节点或进入详情。
3. `Atlas / List` 两种一等视图，切换后保留搜索和筛选条件。
4. Atlas 使用 56 个正式测试记录：支持缩放、平移、悬停预览、点击详情、重置和基本图例。
5. Atlas 明确标为 `Structural Similarity Map`；不把 UMAP 坐标解释为物理量或甜度机理。
6. 基于现有可靠字段的基础筛选：甜度范围、分子量、LogP；没有可靠分类数据前不展示天然/合成筛选。
7. 浏览器返回后恢复 Atlas 的缩放、筛选、搜索和滚动状态。

**V1 必须完成：分子详情页**

1. 顶部摘要：名称、二维结构、分子式、分子量、相对甜度、数据状态。
2. 粘性锚点导航；移动端改为紧凑 section selector。
3. 首版实际内容区块：
   - `Overview`
   - `Sweetness`
   - `Structure & Identifiers`
   - `Physicochemical Properties`
   - `Similar Compounds`
   - `Literature & Evidence`
   - `Data Sources`
4. 缺失数据不渲染虚假的 `0` 或大量 `N/A`；使用明确的 unavailable、not yet curated、predicted 状态。
5. 相对甜度暂时展示现有测试值，但旁边固定显示参照物/实验条件缺失提示，数据结构为未来的范围与条件预留位置。

**V1 必须完成：相似性与比较**

1. 局部相似性网络仅提供两种可解释关系：`Structure` 与 `Sweetness proximity`。
2. 每次只显示 8-15 个邻居，具有阈值、图例、重置和明确的相似度分数。
3. 点击邻居先显示快速预览，并可进入详情或加入比较。
4. 比较最多 3 个分子，V1 比较现有可靠字段：结构、相对甜度、分子量、LogP、TPSA、氢键、QED/SA 等。
5. 结构相似和甜度接近必须分栏或切换显示，不在同一张图中混成一种关系。

**V1 的 Literature 范围**

- 完成 LiteratureCard、标签、空状态、loading、error 和 DOI 外链的前端组件。

**V1 验收标准**

2. Atlas、List、详情、相似网络和比较之间可以完整往返，不丢状态。
3. 所有 56 个测试分子均可进入详情；数据缺失不会破坏布局或显示为误导性数值。
4. 任何相似度、甜度和文献关系均能看出其类型、数据状态或来源。
5. 桌面和移动端无文字遮挡、溢出或无法退出的交互。
6. 页面不宣称 `500+ records`，不把训练集、预测值或 mock 内容冒充正式数据库事实。

## 累计方向（第 5 轮更新）

- V1 聚焦一条完整主流程和两个核心可视化，不追求一次填满未来数据库的所有内容。
- V1 的成功标准是可用、可信、可扩展，而不是可视化数量最多。

## 2026-08-04 第 6 轮

### D-008 详情页信息层级、相对甜度分级与文献提及

**状态：已在本地 V1.2 原型实现**

1. 详情页侧边导航删除 `On this page`，提高锚点字号和字重；`Back to explore` 改为明确的描边按钮。
2. 页面统一使用 `Relative Sweetness`。视觉分级固定为：小于 1 灰色、1 到小于 10 绿色、10 到 1000 黄色、大于 1000 红色。边界值 10 归黄色，1000 归黄色。
3. 测试工作簿中的 `IUPACName Placeholder` 与 `DUMMYKEY` 不再作为科研字段显示，统一规范化为缺失值，等待新数据库填入经验证的标识符。
4. Literature 卡片可接收题目、作者、年份、期刊、DOI、PubMed ID、命中摘录和关联字段；DOI 优先跳转，缺失 DOI 时回退 PubMed。
5. RAG 中精确关键词命中的文献标为 `Indexed mention`。这类记录可用于发现“提及该分子的论文”，但不能仅凭关键词命中宣称论文支持某项科学结论；人工或结构化证据链可单独标为 `Curated evidence`。
6. 二维结构图不再先请求当前不可用的 RDKit 接口。详情图直接使用可靠回退，列表图启用延迟加载；数据契约新增 `structure2dUrl`，供正式数据库使用预生成的本地 SVG/WebP 静态资源。
7. 面向 2,000–3,000 条记录时，结构图应在数据入库阶段批量生成并缓存，列表采用分页或虚拟滚动；不应在用户打开列表时即时生成全部图片。
8. 当前 56 条测试记录含明显占位与未验证描述符，界面统一标为 `prototype records/workbook`，不得使用 `curated` 描述；正式数据库完成来源核验后再升级状态。
